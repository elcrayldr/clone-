# CRAY LDR — DRUMKIT CLONE

Windows x64 VST3 drum-kit extraction and sampler project.

## Current development status

**Milestone 0.2 — Audio import, transient slicing and 64-pad playback prototype**

Implemented in the current development branch:

- JUCE 8.0.6 CMake VST3 project.
- Windows GitHub Actions build workflow.
- 64 pads mapped to MIDI notes 36–99.
- Procedural drum voice fallback for empty pads.
- WAV and AIFF file decoding through JUCE audio formats. MP3 support remains planned.
- First-pass 5 ms energy-peak transient detection with a 75 ms refractory interval.
- Up to 64 detected segments loaded into pads in chronological order.
- Sample playback from GUI pad clicks and MIDI note-on messages.
- Linear interpolation for playback-rate conversion.

**This is still a prototype, not the finished Drumkit Clone product.** It does not yet perform neural source separation, robust drum-family classification, similarity clustering, manual waveform editing, kit export, or MIDI pattern export. The current transient detector is intentionally basic and can miss quiet hits or detect non-drum transients.

## Target product

- Import full songs and instrumentals (WAV, AIFF, MP3).
- FAST mode: DSP transient detection and segmentation.
- AI mode: local neural drum/percussion source separation, followed by detection.
- Classify and group kicks, snares, claps, hats, toms, percussion, and cymbals.
- 64 pads across four banks, MIDI notes 36–99.
- Per-pad sample editing, velocity, choke groups, and audition.
- Export individual WAV files, complete kits, and MIDI patterns.
- Offline operation after model/runtime installation.

## Build requirements

- Windows 10/11 x64
- Visual Studio 2022 with **Desktop development with C++**
- CMake 3.22 or newer
- Git
- Internet access on first configure to fetch JUCE 8.0.6

## Build

From a Visual Studio 2022 Developer PowerShell:

```powershell
cmake -S . -B build -A x64 -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
```

The VST3 target is generated by JUCE under the build artefacts directory. GitHub Actions builds the project on Windows and publishes a VST3 artifact when the build succeeds.

## Architecture direction

The extraction pipeline is intentionally separated into stages:

1. Audio import and decoding
2. Optional local AI source separation
3. Transient/onset detection
4. Feature extraction and drum-family classification
5. Similarity clustering and variation grouping
6. Sample reconstruction and editing
7. MIDI sampler and kit export

AI separation must not be represented as simple slicing. Model licensing, redistribution rights, runtime footprint, and offline inference performance must be checked before selecting and bundling a model.

## Known prototype limitations

- Import analysis currently runs from the editor's file-selection callback; moving decode and detection to a background worker is required before production use.
- Detection is based on short-window energy peaks, not a trained drum detector.
- Segments are assigned by time order, not by drum-family classification.
- No project-state persistence or kit export yet.
- The sample player is mono at present.
- Sample data is retained for the lifetime of the plugin instance to keep audio-thread sample access free of shared-pointer reference-count destruction; imports are capped at 256 retained segments per instance. Restart the plugin to reset this safety limit.
